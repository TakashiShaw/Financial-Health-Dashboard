# Prompt Log

This file summarizes the main ways I used AI tools while building the Company Financial Health Dashboard for CMU 15-113 Project 2.

## 1. Project Planning

I asked ChatGPT to help turn my initial idea into a realistic Project 2 plan.

Main goal:

- Build a dashboard that combines business/finance, SEC data, Python calculations, visualization, and an optional AI explanation layer.

Important guidance from AI:

- Focus on a strong MVP before stretch features.
- Use Flask as a backend because SEC data should not be fetched directly from frontend JavaScript.
- Keep the project understandable enough to explain in class.
- Add AI as an interpretation layer only after the program calculates factual metrics.

## 2. Initial Flask Scaffold

I prompted Codex in VS Code to scaffold a beginner-readable Flask app.

Requested files included:

- `app.py`
- `sec_client.py`
- `financial_metrics.py`
- `templates/index.html`
- `static/styles.css`
- `static/app.js`
- `requirements.txt`
- `README.md`

The first version used mock AAPL data so the frontend could be tested before SEC integration.

## 3. UI Iteration

I used AI to improve the initial generic dashboard layout.

Changes requested:

- Make the app feel more like a practical finance dashboard.
- Reduce the large landing-page feel.
- Use a compact app header, financial tables, tabs, and integrated charts.
- Use StockAnalysis-style financial pages as loose inspiration without copying branding or text.

## 4. SEC EDGAR Integration

I prompted Codex to replace mock data with real SEC EDGAR data.

Main requirements:

- Fetch SEC's ticker lookup JSON.
- Match a user-entered ticker.
- Convert the company's CIK to the 10-digit SEC format.
- Fetch Company Facts JSON.
- Use a proper SEC User-Agent header.
- Return clean errors for invalid tickers and request failures.

This became the core of `sec_client.py`.

## 5. Financial Metric Calculations

I used AI to help build `financial_metrics.py`.

The app extracts annual 10-K data for:

- Revenue
- Net income
- Operating income
- Assets
- Liabilities
- Cash

The app calculates:

- Revenue growth
- Net profit margin
- Operating margin
- Liabilities/assets
- Return on assets

AI helped identify the need for fallback XBRL concept names because companies do not always report the same financial idea under exactly the same tag.

## 6. Missing Data Handling

When Nike did not show an operating margin line, I asked AI to investigate.

Result:

- Nike did not provide a true `OperatingIncomeLoss` concept in the SEC data being used.
- Pretax and nonoperating income concepts were not used as substitutes because that would be misleading.
- The frontend was updated to hide chart datasets when every value is missing.

This was an important data-cleaning decision: the app should show `N/A` rather than fake or estimate values.

## 7. Programmatic Key Observations

I prompted AI to add observations generated by Python calculations, not by an AI model.

The app now compares the latest fiscal year with the prior fiscal year and creates factual observations such as:

- Revenue increased or decreased by a percent.
- Net income increased or decreased by a percent.
- Net profit margin improved or declined by percentage points.
- Operating margin improved or declined when available.
- Liabilities/assets increased or decreased when available.

These observations are included in the API response under `observations`.

## 8. OpenAI Explanation Layer

I prompted AI to add an optional OpenAI-powered explanation feature.

Important constraints:

- The API key must stay server-side.
- The key is read from `OPENAI_API_KEY`.
- The frontend never sees the key.
- The model receives only structured metrics and observations already calculated by the app.
- The AI must not fetch company data or invent numbers.
- The explanation includes an educational-use disclaimer.

The implementation added:

- `ai_explainer.py`
- `/api/explain/<ticker>`
- A "Generate AI Explanation" button in the frontend

## 9. Debugging The AI Explanation

The first OpenAI response returned an empty explanation.

AI helped debug the issue by checking the backend endpoint directly and updating the request to use:

- minimal reasoning effort
- a larger output token limit
- a clear error if OpenAI returns no text

After this fix, `/api/explain/AAPL` returned a full explanation.
